System Design in 60s · Ep 05: Latency vs throughput vs bandwidth. Kodo's manager said "bandwidth double kar do, app fast ho jayega." Kodo nodded. REJECTED. 🛣️  
  
Think of the Mumbai–Pune expressway. Lanes = bandwidth. One car's trip time = latency. Cars arriving per hour = throughput.  
  
Double the lanes and more cars get through. But Pune is just as far, so each car still takes the same time.  
  
Small API call slow? That's latency, not bandwidth.

🚀 Latency vs Throughput — Two metrics every backend engineer should understand.  
  
• Latency: The time it takes for a single request to complete.  
• Throughput: The number of requests a system can process per second.  
  
How to reduce latency:  
✅ CDN  
✅ Read Replicas  
✅ Caching  
✅ Database & API optimization  
  
How to increase throughput:  
✅ Load Balancing  
✅ Horizontal Scaling  
✅ Multiple application instances  
✅ Asynchronous processing  
  
Mastering these concepts is essential for building fast, scalable systems and performing well in system design interviews.
